# ALL LIFE: Agent Instructions

ALL LIFE is a creative brand and portfolio. Its first product line is handcrafted belts made from upcycled bike tyre with sand-cast aluminium buckles. The website is one **spatial canvas** (a board you pan and zoom, like a mood board or Miro) with a cinematic entry, a film, a circular photo collage and a shop where customers purchase by email.

The landing page (a spinning 3D seal with a "Click to enter" idea) already exists in this repository and is live. Everything else is built in phases. Read `docs/00-product-brief.md` first, then the brief for the current phase in `phases/`.

## Stack (existing repo, keep it)

- Vite 5, React 18, TypeScript, React Router 6, Tailwind CSS, shadcn/ui, TanStack Query, react-hook-form, Zod. The repo was generated by Lovable; remove generator leftovers only after asking.
- Backend: **Supabase only** (Postgres with row-level security, Auth, Storage, Edge Functions). Vercel hosts the front end only.
- Added during the build (approved list): `@supabase/supabase-js`, `zustand`, `@use-gesture/react`, `framer-motion` (or `gsap`, pick one and record it), `hls.js`, `vitest`, `@testing-library/react`, `jsdom`, `@playwright/test`, `@axe-core/playwright`, `@sentry/react`. `pixi.js` only if the collage needs it (see `docs/02-canvas-spec.md`). Any other dependency needs a line in `docs/decisions.md` first.
- Package manager: **npm**. Do not delete `bun.lockb` or `package-lock.json` without asking the owner.

## Commands

Create any script that is missing, then keep these names stable.

```
npm run dev          # Vite dev server
npm run build        # production build
npm run typecheck    # tsc --noEmit
npm run lint         # eslint
npm run test         # vitest run
npm run test:e2e     # playwright (chromium + webkit)
npx supabase start   # local Supabase stack
npx supabase db reset
npx supabase test db # pgTAP tests
npx supabase gen types typescript --local > src/lib/database.types.ts
```

## Layout (target)

```
src/app/            routes, providers, layout
src/canvas/         engine only: camera, world, regions, nodes, gestures, viewpoints
src/features/       entry, film, collage, shop, enquiry, admin (feature code lives here)
src/components/ui/  shadcn components
src/lib/            supabase client, env, utils, generated database types
supabase/           migrations, seed.sql, functions/, tests/
scripts/            encode-hls.sh, upload-film.ts, seed scripts
e2e/                Playwright specs
docs/  phases/      specifications and phase briefs
```

`src/canvas` must never import from `src/features`. Features import from the canvas, never the reverse.

## Working rules

1. Work on **one phase at a time**. Read the phase brief, do its tasks in order, and do not build ahead.
2. Do not change the look or behaviour of the existing landing page except through the integration points named in Phase 1. Record how it works in `docs/landing-audit.md` before touching it.
3. TypeScript strict for all new code. No `any`. Validate every external input with Zod. Use generated Supabase types.
4. No secrets in the client. Only `VITE_`-prefixed variables reach the browser, and they must be safe to be public. The Supabase **service-role key** is only ever used in local scripts and Edge Functions.
5. All data access goes through supabase-js under row-level security. Every table has RLS enabled and tests proving anonymous users can read only published rows and write nothing.
6. Accessibility and reduced motion are requirements, not polish (WCAG 2.2 AA; `prefers-reduced-motion` respected; no flashing above 3 Hz).
7. Mobile first. iPhone Safari is the reference browser for video and gestures. Use `dvh` units, `playsInline`, and test on a real device before calling a phase done.
8. Performance budgets are in `docs/04-design-and-motion.md`. Do not exceed them without recording why.
9. Tests are part of every task (see `docs/05-testing-and-quality.md`). A task without tests is not done.
10. When a decision is not covered, look in `docs/decisions.md`. If there is a default, use it. If not, stop and ask the owner a specific question, then record the answer. Do not guess about content, pricing, copy or brand.
11. British English in all user-facing copy and in docs (colour, moulds, tyre).
12. Small commits in Conventional Commit style (`feat(film): ...`, `fix(canvas): ...`, `test: ...`). One branch per task: `phase-1/t06-entry-sequence`. Open a PR per task or per small group of tasks.

## Out of scope for v1 (do not build)

Online payments, a cart, inventory sync, visitor accounts, native apps, multiple languages, a drag-and-drop layout editor, automatic film transcoding in the admin.

## Definition of Done (every task)

- Acceptance criteria in the phase brief are met and demonstrated.
- `npm run typecheck`, `lint`, `test` and `build` pass; relevant e2e specs pass on Chromium and WebKit.
- No new accessibility violations in axe on the touched screens.
- Budgets in `docs/04-design-and-motion.md` still hold.
- Docs updated: the phase checklist ticked, `docs/decisions.md` updated, new env vars added to `.env.example`.
- A short note on what to test by hand on a real iPhone and an Android phone.
